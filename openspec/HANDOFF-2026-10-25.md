# Handoff — 2026-10-25

> **Qué es**: el prompt de arranque para una ventana nueva de Compass, congelado en el repo para
> no depender de copiar y pegar desde un chat.
>
> **Cómo se usa**: pegá el bloque de abajo tal cual en un chat nuevo. La ventana lee el estado del
> repo (`BACKLOG-100.md`, `PENDIENTES-FUNCIONALIDAD.md`, `git log`) y no necesita nada de este hilo.
>
> **Cuándo regenerarlo**: al cerrar cada unidad de trabajo, para que el estado esperado del punto 2
> siga siendo cierto. Si el `git log` ya lo desmiente, actualizá este archivo antes de usarlo.

---

```text
Retomá Compass. Es una ventana nueva: leé el estado antes de proponer nada.

1) Leé en este orden:
   - AGENTS.md (reglas del repo; monorepo en k0mp4ss_fe/, app en apps/web)
   - openspec/BACKLOG-100.md → §"Cierre del 2026-10-25", al final del archivo
   - openspec/PENDIENTES-FUNCIONALIDAD.md → el ledger vivo
   - git status -sb && git log --oneline -5

2) Decime dónde estamos en 6 líneas y qué frente proponés; todavía no escribas código.

Estado esperado al cierre del 2026-10-25 (verificalo, no lo asumas):
- main en 1e23420, árbol limpio, sin PRs abiertos.
- Mergeados: #11 automatismos CO · #12 F1 + tres fugas de CO · #13 F2/F3 · #14 ledger ·
  #15 F11 paginación + F12 obsoleta · #16 capacidad de F6.
- Changes archivados: co-lectura-residente y metricas-reales-backup-descarga.
- openspec validate --all 36/36.

Reglas que costaron caro en la sesión anterior — respetalas:
- No entregues nada sin verificarlo. Si un e2e no pasa tras dos o tres intentos con hipótesis
  distintas, PARÁ y reportá el bloqueo con evidencia; no sigas adivinando.
- El job `unit-PG` corre la misma suite contra PostgreSQL: cualquier SQL de dialecto
  (INSERT OR IGNORE) o una carrera sobre una caché derivada SÓLO aparece ahí. Si algo falla
  sólo en PG, el defecto es del test o del modelo, no "flakiness".
- `npm run audit:desvios` es candado: si marca, se arregla el código, no se silencia
  (R4 marca hasta `iso.slice(0,10)`).
- ESLint no lee .gitignore: correr la lane e2e en local deja miles de warnings de
  playwright-report. Ya está ignorado en eslint.config.js; no lo "arregles" a mano.
- Para verificar e2e en local: `npm run e2e:fresh -- -- <spec>`. El log del job en GitHub

Frentes:

  F8 SDK de identidad, F9 retirar QA/dev, F10 dominios del allowlist.

¿Empezamos por F6, o preferís otro frente?
```

## Variantes

- **Trabajo chico y verificable**: cambiá la última pregunta por «Arrancá por el fixture de
  unidades en la lane (sin él, F6 no se puede verificar)».
- **Varias ventanas encadenadas**: pedile el skill `serie-ventanas`; materializa los prompts en
  `openspec/SERIE-<slug>/` y la reanudación lee el estado del repo, no del chat.

## Por qué el prompt dice lo que dice

Cada regla del punto «costaron caro» corresponde a un tropiezo real de la sesión del 2026-10-25:

| Regla | El tropiezo |
| --- | --- |
| Parar tras dos o tres intentos | Seis corridas de e2e (~50 min) persiguiendo un término de búsqueda mientras la causa era otra: el padrón vacío |
| Mirar `unit-PG` | Un test con SQL de dialecto SQLite, y otro que afirmaba consistencia de una caché que el diseño declara ignorada — invisibles en SQLite |
| El candado se arregla, no se silencia | R4 marcó `iso.slice(0, 10)` sobre una fecha como si fuera un recorte de lista |
| ESLint no lee `.gitignore` | El lint saltó de 1 a 3.793 warnings por el reporte HTML de Playwright |
| La causa está en el artefacto | El log del job e2e viene truncado; `junit.xml` y `error-context.md` son la evidencia |
