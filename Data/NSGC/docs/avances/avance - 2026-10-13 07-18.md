## ✨ Hitos Logrados

1. **`npx tsc --noEmit` en el job `unit-pg`** (`.github/workflows/ci.yml`), después
   de `npx prisma db push` y con el mismo `working-directory`: el esquema PG ahora
   también se tipa en CI, en paridad con el job SQLite. YAML validado con
   `python3 -c "import yaml; yaml.safe_load(...)"`.
2. **npm local vs CI**: `k0mp4ss_fe/package.json` declara `engines.npm: ">=11"`
   (junto a `node >=24`) y `README-DEPLOY.md` documenta la regla: Node 24.21.0 trae
   npm 11.19.0 (mismo npm 11 del CI), npm 12 es compatible porque el lockfile usa
   `lockfileVersion: 3`, el lockfile no se regenera por diferencia de npm, y el
   `packageManager: "npm@10.8.2"` es un pin histórico inerte (no hay shim de
   corepack para npm). `.npmrc` del monorepo vacío → sin `engine-strict`.
3. **`npm run e2e:fresh`** (`scripts/e2e-fresh.mjs`): recrea una base descartable
   `prisma/perf*.db` desde el schema SQLite (`prisma migrate deploy
   --schema=prisma/schema.sqlite.prisma` con `DATABASE_URL` propio), corre
   `npm run e2e:reseed-base` contra ESA base, imprime en grande las dos
   advertencias duras (base fresca por corrida; nunca el spec de rate-limit
   primero: bloquea la IP 15 minutos) y termina con el comando Playwright exacto
   con paridad CI. Guard explícito contra `prisma/dev.db` (validación de nombre +
   `DATABASE_URL` fijado para los subprocesos: `process.env` pisa al `.env`,
   comprobado con `node --env-file-if-exists` y `vite-node`). Documentado en
   `docs/runbook-operaciones.md` (nuevo escenario "Lane e2e local (base fresca)").
