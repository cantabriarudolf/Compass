# Avance de Desarrollo - 2026-10-24

## 📋 Resumen: el selector de unidad ya busca en toda la comunidad, no en las 100 primeras

La unidad **F6** de `openspec/PENDIENTES-FUNCIONALIDAD.md` señalaba que los selects de
unidad/persona montan hasta 100 opciones y, desde el PR #7, **avisan** el recorte, pero no
permiten buscar el resto. Con 300 unidades el conserje tenía que refinar por otro camino para
encontrar la unidad destino de una visita.

Ahora el `Select` de **Unidad destino** de visitas es un campo de búsqueda: el término viaja a
`GET /api/unidades?q=`, que filtra sobre **toda la comunidad** (número, etiqueta y rol SII) con
el mismo scoping de sesión y la misma paginación. El aviso de truncamiento de ese campo
desapareció porque ya no hay lista recortada que avisar.

## ✨ Hitos Logrados

1. **Búsqueda por texto opt-in en el factory** (`lib/api/crud-factory.ts`): nueva opción
   `busqueda?: { campos: string[] }`. Con `?q=` el `where` del GET suma un `OR` de `contains`
   sobre esos campos; **sin la opción o sin `q` el `where` es exactamente el de hoy**
   (`{ comunidadId }`), así que las decenas de rutas que usan el factory no cambian. No se usa
   `mode: "insensitive"` porque SQLite (dev y suite) no lo soporta y su `LIKE` ya es
   case-insensitive para ASCII.
2. **Unidades busca por sus identificadores visibles** (`app/api/unidades/route.ts`):
   `numero`, `etiqueta` y `rolSii`. Son los datos que el conserje tipea o lee en documentos;
   los ids internos y las FKs no se buscan. El `total` se calcula con el mismo `where` filtrado.
3. **`components/selector-buscable.tsx`**: combobox genérico (sirve para unidades y personas)
   con `buscar(q)` provisto por el consumidor. Debounce de 300 ms, mínimo 2 caracteres,
   cancelación de respuestas viejas por secuencia, valor actual siempre visible aunque no esté
   en los resultados, navegación con teclado (flechas/Enter/Escape), roles combobox/listbox,
   foco visible y estados de carga/vacío («Sin resultados para "x"»).
4. **Pantalla cableada — `/operaciones/accesos` y bitácora, pestaña Visitas**
   (`components/pe/visitas-panel.tsx`): el campo «Unidad destino» usa el selector y se quitó su
   `AvisoTruncamiento`. Si la API no responde o la sesión no tiene permiso de gestión, el
   consumidor cae al padrón local **completo** (nunca solo las 100 primeras), así que la
   operación de conserjería no se bloquea.
5. **Tests primero (TDD)**: `test/lib/crud-factory-busqueda.test.ts` (6),
   `test/api/unidades-busqueda.test.ts` (7) y `test/componentes/selector-buscable.test.tsx` (7).
   ROJO observado: 3 archivos fallando, **8 tests rojos / 5 verdes** (el archivo del componente
   ni siquiera resolvía el import); GREEN: **20/20**.
