# Avance de Desarrollo - 2026-10-27 (ventana 12-05)

## 📋 Resumen: la base de Neon queda conectada y los seeds dejan de sembrar la base equivocada

La ventana anterior dejó `.env` apuntando a Neon, pero **cuatro de las cinco scripts de datos no
podían correr**. El síntoma («the URL must start with the protocol postgresql://») tenía **dos
causas sumadas**, y ninguna era la que se sospechaba:

1. **La línea `DATABASE_URL` de `.env` estaba corrupta**: el pegado de la cadena de Neon se encimó
   sobre la vieja de SQLite y quedaron **dos valores en la misma línea**. `node --env-file`
   (que usa `seed:authz`) recorta la comilla y arma una URL válida; `dotenv` (que usan las otras
   cuatro) se queda con el pegote. Por eso una semilla andaba y las demás no.
2. **`.env.local` ganaba por izquierda**: `vite-node` carga `.env.local` (`file:./dev.db`) y lo
   deja en `process.env`, y `dotenv.config()` **no pisa** lo que ya está. El `config({ path })`
   de las scripts no hacía nada para esa clave. El setup de tests **no** era el culpable: se
   verificó que `vite-node --config vitest.config.ts` no ejecuta `test.setupFiles`.

## 🔧 Qué quedó hecho

- **`lib/database-url.ts`**: resuelve la URL entre entorno, `.env` y `.env.local` y elige la
  primera **compatible con el proveedor del cliente Prisma generado** (`node_modules/.prisma`).
  Normaliza comillas accidentales, detecta la concatenación corrupta y, cuando no hay ninguna
  usable, aborta con un mensaje que nombra el archivo y el protocolo esperado —**nunca el valor**.
  El entorno sólo cede si su valor es el default declarado en un archivo `.env*`: si lo exportó
  CI/e2e/la suite, la discrepancia es error explícito, no un cambio silencioso de base.
- Las **cuatro** scripts (`seed:mocks`, `db:catalogo-nacional`, `db:punto-cero`, `db:fondos-fi`)
  usan ese módulo. `--config vitest.config.ts` se mantiene por el alias `@/`, no por herencia.
- **Esquema de Neon alineado**: `prisma db push --accept-data-loss` (el flag lo pedían dos índices
  únicos, no un borrado) y verificación con `migrate diff` → *«This is an empty migration»*.
- **Datos sembrados y medidos** en `comunidad-a`: 166 unidades · 55 personas · 52 vínculos ·
  216 egresos (182 del punto cero + 34 preexistentes) · 44 ingresos · 7 fondos; catálogo nacional
  38 filas × 3 comunidades = 114. Los upserts no borran: el delta ya estaba.
- **`/api/health` con la app apuntando a Neon**: `HTTP 200 · checks.database=ok · checks.auth=ok`.
- **Deploy**: el job corre `prisma db push --skip-generate` antes de `vercel build`, con el secret
  `DATABASE_URL` y **sin** `--accept-data-loss`, porque `migrate deploy` no puede ser el camino
  mientras los dos schemas compartan `prisma/migrations` lockeado a sqlite (P3019).
- **Suite**: se arregló el rojo que arrastraba `main` desde `7801484`. F18 descarta los campos
  previsionales sin consentimiento **antes** de validar las FKs (contrato buscado), así que el
  caso «FK laboral inexistente → 400» no llegaba a validar nada. Se arregló **el test**, que
  ahora declara el consentimiento para probar la regla de FK.
