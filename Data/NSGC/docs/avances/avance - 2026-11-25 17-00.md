# Avance de Desarrollo - 2026-11-25

## 📋 Resumen: un interruptor para los dos juegos de datos

Para las pruebas manuales hace falta poder vaciar la base, dejar los defaults del sistema y cargar las
planillas como lo haría un administrador. Faltaba la vuelta: `backup:db` y `restore:db` son del carril
SQLite, así que vaciar Postgres era de una sola dirección.

`npm run jdd` cubre el ciclo: `estado` (a qué base apunta y cuántas filas por tabla), `snapshot`
(rama de Neon como copia de seguridad), `wipe`, `seed` y `restore <rama>`. Todos aceptan `--dry-run`.

## ✨ Hitos Logrados

1. **Guarda única y explícita**: `wipe` y `restore` exigen `--confirmo=BORRAR` literal; sin eso
   imprimen el plan y salen con código 2. El plan se imprime **siempre** antes de tocar nada.
2. **Orden de tablas por dependencias**, leído de `pg_constraint`, no una lista fija: el esquema cambia
   y una lista fija se rompe en silencio.
3. **`restore` transaccional**: lee de la rama de Neon por cursor (no carga tablas enteras en memoria),
   escribe una transacción por tabla en lotes de 500 y, si una falla, corta ahí en vez de dejar
   huérfanos.
4. **`_prisma_migrations` no se toca nunca**: vaciarla rompería `migrate deploy` para siempre.
5. **Nunca imprime la cadena de conexión**: muestra host y nombre de base.
