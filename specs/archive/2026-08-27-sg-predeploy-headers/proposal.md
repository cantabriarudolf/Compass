# Proposal: sg-predeploy-headers — D-i/ii/iii CSP report-only + headers + re-chequeos scripted

## Why
SG §3 Fase D exige pre-deploy: D-i CSP estricta en report-only con nonces/hashes para inline de Next, D-ii headers contra dominio definitivo configurable (PUBLIC_DOMAIN, HSTS sin preload) y D-iii conversión de re-chequeos manuales en script repetible. La auditoría `consolidado - 2026-08-24-b` lista C1–C3b (cerrados P2–P3), D-v (cerrado P5) y deja D-i/ii/iii pendientes. P5 cerró Auth.js+rate-limit persistente; la app aún corre dev (Google Fonts sin red rompe `next build`), por lo que `next dev`+curl es el límite documentado. El dominio real de producción aún no existe (decisión owner): todo dominio SHALL ser env configurable, no hardcodeado. `next.config.mjs:2-8` ya tiene securityHeaders base (HSTS includeSubDomains, DENY, nosniff, Referrer-Policy, Permissions-Policy) y `proxy.ts:1-31` protege `/admin`/`/api` con Auth.js; `lib/env-guard.ts` y handlers (`/api/backup`, `/api/dev-dashboard`) ya implementan 413/404, `lib/dev-dashboard.ts:464` sanea `changeId` con `SAFE_CHANGE_ID`. Esta ventana convierte esa base en D-i/ii/iii verificables: CSP report-only nonce vía proxy, headers verificados/complementados con PUBLIC_DOMAIN, y los 5 re-chequeos D-iii en script que imprime OK/FAIL y falla si algo no pasa.

## What Changes
- **D-i — CSP report-only**: `proxy.ts` genera nonce por request (`crypto.randomUUID()` → base64) y añade `Content-Security-Policy-Report-Only` con orígenes auditados: `self`, imágenes remotas `https:`/`data:`/`blob:` (placeholder/logo/aviso CV), YouTube embeds (`frame-src https://www.youtube.com https://www.youtube-nocookie.com`), fonts (`style-src`/`font-src` `https://fonts.googleapis.com` `https://fonts.gstatic.com` + `self` `unsafe-inline`/`data:` por Next), `script-src 'self' 'nonce-{x}' 'strict-dynamic' 'unsafe-inline' 'unsafe-eval' https:` (Next inline + dev), `connect-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`. No se fuerza (`Content-Security-Policy` no se emite) en esta ventana; solo Report-Only. Telemetría y plan enforcement documentados en `design.md` (qué revisar, umbrales, cuándo forzar).
- **D-ii — Headers dominio configurable**: `.env.example` documenta `PUBLIC_DOMAIN=` (vacío, owner define dominio real; no hardcodear). `next.config.mjs` mantiene/verifica `securityHeaders` existentes, añade complementos (`X-DNS-Prefetch-Control`, `X-Permitted-Cross-Domain-Policies`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`) y conserva `Strict-Transport-Security: max-age=63072000; includeSubDomains` **sin** `preload` mientras no haya dominio real (documentado que `preload` se activa con dominio). Expone `npm run check:headers` (`scripts/check-headers.mjs` + o test) que imprime headers (lectura estática de `next.config.mjs` + `proxy.ts` CSP + `curl` vivo si `next dev` corre) para verificación manual/`securityheaders.com`.
- **D-iii — Re-chequeos scripted**: `scripts/security-recheck.mjs` (node, invoca handlers directamente sin necesitar `next start`) + `test/security-rechecks.test.ts` (vitest integración, misma cobertura) verifican 5 casos imprimiendo OK/FAIL y con exit 1 si falla: (1) `POST /api/backup` >10MB → 413, (2) APIs escritura con `APP_ENV=production` → 404, (3) path traversal `changeId="../../etc/passwd"` en `toggleTask`/dev-dashboard → 404/sanitizado, (4) `GET /admin/*` sin cookie → redirect 307/308 a `/ingresar?next=`, (5) `GET /api/admin/usuarios` o `/api/*` sin sesión → 401. Usa puerto efímero si se integra con `next dev`, pero por defecto invoca handlers (estable en CI sin build).
- **Spec delta**: `SG-hardening-despliegue` MODIFIED con 3 requisitos nuevos D-i/D-ii/D-iii verificados.
